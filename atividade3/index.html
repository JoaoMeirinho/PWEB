Arquitetura de Software

Do monólito aos microsserviços: fundamentos, padrões e tendências

Definições Tipos de Arquitetura Padrões e Protocolos Tomada de Decisão Tendências

1. Definições formais de Arquitetura de Software

A Arquitetura de Software é o alicerce estratégico do desenvolvimento de sistemas, representando a ligação entre as necessidades de negócio e a viabilidade técnica. A norma ISO/IEC/IEEE 42010:2011 a define como a organização fundamental de um sistema, incorporada em seus componentes, relacionamentos e princípios de design.

Decomposição

A decomposição gerencia a complexidade cognitiva, transformando problemas grandes em módulos menores. Existem dois paradigmas principais:

  • Decomposição Funcional: baseada em processos e verbos, com refinamento sucessivo de funções.
  • Decomposição Orientada a Objetos: baseada em entidades e substantivos, focando no domínio do problema.

Segundo Parnas (1972), um bom módulo é aquele que oculta decisões de design, permitindo substituição sem afetar o sistema global.

Pilares da Programação Orientada a Objetos

  • Abstração: extrai aspectos essenciais, reduzindo a carga cognitiva.
  • Encapsulamento: restringe o acesso direto aos dados.
  • Herança: promove reuso, respeitando o Princípio de Liskov.
  • Polimorfismo: permite que objetos diferentes respondam à mesma interface.

2. Tipos de Arquitetura de Software

Monolito Tradicional

Um único executável e base de código unificada. É simples de gerenciar, mas o escalonamento (via WebGarden ou WebFarm) exige replicar o bloco inteiro, gerando ineficiência de recursos.

Monolito Modular

Um "caminho do meio", organizado com base em Domain-Driven Design e Bounded Contexts. Prepara o sistema para uma futura migração através do Strangler Application Pattern (Transform, Coexist e Remove).

Microsserviços

Aplicação distribuída com implantação independente, escalabilidade seletiva e heterogeneidade tecnológica. Exige padrões como API Gateway, BFF e Saga Pattern para lidar com a consistência eventual (BASE).

3. Padrões de Projeto e Protocolos de Comunicação

Domain-Driven Design (DDD) e Bounded Context

Ferramenta estratégica de Eric Evans para garantir alta coesão e baixo acoplamento, modelando o sistema em torno de capacidades de negócio.

Backend for Frontend (BFF)

Otimiza a comunicação entre backend e diferentes clientes (web e mobile), consolidando chamadas de múltiplos microsserviços em uma resposta única.

Service Discovery e API Gateway

O Service Discovery localiza instâncias efêmeras de serviços. O API Gateway centraliza autenticação, roteamento, segurança e balanceamento de carga.

Protocolos de Comunicação

  • REST: simples e amplamente adotado, mas sofre com over-fetching.
  • GraphQL: permite ao cliente pedir exatamente os dados que precisa.
  • gRPC: alta performance com HTTP/2 e serialização binária.

4. Escolha da Arquitetura e Tomada de Decisão

Não existe uma arquitetura universalmente "melhor". Segundo Richards e Ford, "tudo em arquitetura de software é um trade-off": cada ganho em um atributo (como resiliência) tem um custo associado (como complexidade de rede).

O Quantum Arquitetural é a menor unidade de arquitetura com alta coesão funcional, delimitando a integridade transacional do sistema.

5. Tendências Tecnológicas

Governança Arquitetural

Architectural Fitness Functions são testes automatizados que verificam a conformidade do sistema com seus objetivos arquiteturais, como o isolamento entre camadas.

Micro Frontends

Estende os benefícios dos microsserviços para a interface do usuário, decompondo a tela em módulos autônomos geridos por squads verticais.

Serverless e FaaS

Funções stateless acionadas por eventos, sem gerenciamento de infraestrutura, cobrando apenas pelo tempo de execução.

Gêmeos Digitais (Digital Twins)

Modelos dinâmicos alimentados por dados em tempo real, usando protocolos como MQTT e OPC UA para integrar o mundo físico e o virtual.

Inteligência Artificial como Microsserviços

O paradigma AI as a Microservice (AIMS) permite consumir capacidades preditivas de forma modular, mesmo com restrições de recursos na borda (edge).
